## 1. SHIP GATE (the only finish line — EARS form, falsifiable)
SHIP = WHEN the assertion suite is run over the fixture corpus THE SYSTEM SHALL convert SRT↔WebVTT with byte-identical reference output, millisecond-exact timing preserved across every conversion, and every skipped block reported with a reason — at zero failing assertions.

Evidence required: `RESULTS.json`, written by `verify.sh` (or `verify.ps1`), carrying the measured `value` (`N/N passed, 0 failed`) and `green:true`. The artifact is regenerated by the run, not written by hand — that is what makes it evidence rather than a claim.

Grounding signal (gate every change on this, never "vibes"): `node test/convert.test.js` — the assertion suite; the number that counts is `0 failed`. `bash verify.sh` wraps it and writes the RESULTS.json evidence artifact.

## 3. RAILS (per-type add-on pack — on top of §3a, never replacing it)
- **cli-tool pack:** never write outside an explicitly passed output path; never overwrite the input file in place; exit non-zero on any parse failure so the tool is safe inside a shell pipeline; write data to stdout and diagnostics to stderr so the output can be piped.
- **Format fidelity law:** timing is the product. A conversion that alters a cue boundary by one millisecond is a defect, not a rounding choice. Times are integer milliseconds end to end — never a float.
- **No silent data loss:** a block that cannot be converted is reported with a reason, never dropped quietly. This is rail #6 made concrete for this project.
- STATUS.md is the single source of truth. No doc drift. Hygiene pass every 3 tasks and at session end.
- FREE/OSS only. Zero runtime dependencies is a hard constraint here, not a preference: it is what makes the example runnable on a bare machine.

## 4. LADDER (phases, simplest-first — full acceptance clauses in `PLAN.md`)
- **P0 — timestamp core.** Parse and format both timestamp dialects, integer milliseconds, malformed input rejected loudly.
- **P1 — parser.** One neutral cue model both formats read into; BOM, CRLF, multi-line cues, WebVTT cue settings, NOTE blocks, backwards cues.
- **P2 — emitters + round-trip.** SRT and WebVTT writers; byte-identical against reference fixtures; round-trip drift zero.
- **P3 — CLI + ship.** Argument handling, stdout/stderr split, skip reporting, non-zero exit on failure; `verify` green; RESULTS.json written.

(each phase ends green on the §1 signal before the next begins)
