## 2026-07-27 — data+web lead-gen project (brownfield post-build, v8 epistemic gate)
- **Taught by a GPT-adversarial loop (owner relayed):** "detect absence of an external system" ≠ "reconstruct internal process". The defensible framing: sector prior → externally-verifiable friction (OBSERVED/DECLARED only) → conditional banded impact. Two separate doors: friction-exists vs cost-quantifiable (UNKNOWN/DIRECTIONAL/QUANTIFIED).
- **Pattern worth generalizing into the machine:** gap strength = key × mode of proof, not key alone (PITCH_POLICIES beats a STRONG_KEYS set); DISTINCT quarantine reason codes because each demands a different fix; per-CLAIM coverage (INSUFFICIENT_COVERAGE ≠ CONFIRMED_ABSENT); a descriptive observation (offline payment channel) must never be a pitchable pain by itself.
- **Locked gate order:** entity/site corroboration → ICP eligibility → coverage → validation → pitch policy → send gate. A garbage site (Yahoo Finance stored as website — real defect found in DB) fails before eligibility.
- Outcome: selftest 184→213 green, send-ready pool unchanged (no regression), 3 passive LMNP holdings + 7 platform-only leads newly coded distinctly.

## 2026-07-27 (bis) — data+web project, re-scrape postmortem
- A smoke test (3 rows) passing does NOT validate a full run against rate-limiting: the ban arrived MID-RUN (227/227 blocked after smoke was fine). Circuit breakers must live INSIDE the loop, not in the pre-flight.
- The baseline-snapshot-with-manifest protocol (insisted on by the adversarial GPT reviewer) paid for itself the same day: 134 degraded rows, full restore, zero loss.
- Generalize into _TEMPLATE doctrine: any batch job that OVERWRITES rows needs (a) a never-degrade guard (lost data = failed fetch, not new knowledge), (b) an in-loop circuit breaker, (c) a restorable baseline BEFORE launch.
- (ter) Domain stability lesson: rediscovery must be tier-gated AT THE SINGLE WRITE BOUNDARY (provenance hierarchy: manual lock > corroborated first-party > weak candidate > platform > broker/press), with manual_review locks that no automation may overwrite. A gate that quarantines a degraded lead prevents the LEAK but still loses the LEAD — non-regression must act upstream, at write time.

## 2026-08-06 — Godot 4 game (brownfield, resume-and-fix prompt)

- **EXISTING mode with no greenfield study.** The owner dropped a complete Godot build (6,782 lines of GDScript, 2 scenes) into a project folder and asked for "the most complete fix prompt possible". Native mapping (`Read`/`Grep` + targeted reads of 5 scripts out of 21) beat any abstract study: it produced the ROOT CAUSE of the blocking bug in four reads — `game_state.gd:668 nouvelle_partie()` resets `point_respawn = Vector3.ZERO` *after* `game_world.gd:830` has computed it, so the first death teleports the player 6.7 m under the terrain. **Generalize: on brownfield, initialization ORDER is the first suspect behind any "physics" bug. Read the `_ready()` sequence before you touch the physics.**
- **"The graphics look broken" on a web-first export is not an asset problem.** `renderer/rendering_method="gl_compatibility"` + `mipmaps/generate:false` + `size_limit:1024` + MSAA 0 is a *web export* configuration applied to a desktop game. **Diagnose the RENDER CONFIG before judging a single asset** — and write it into the prompt as an order of operations (redo the render phase, recapture, THEN re-judge the assets), or the agent replaces perfectly good models.
- **The eval gate is English-bound.** A prompt delivered in French scored 20/100 on the first pass while the substance was actually there (EARS written as "QUAND … LE SYSTÈME DOIT", "signal d'ancrage" for the grounding signal). Two distinct lessons: (a) `tests/eval_prompt.js` matches ENGLISH patterns — for a non-English deliverable, anchor the canonical bilingual form inside the document (which is honest: the EARS form is named); (b) the gate still found TWO real holes — no rails/deny-set, no team. Final score 92/100, with only `materialize_complete` missing, deliberately: the deliverable was a self-contained prompt for an EXTERNAL agent, not a `_TEMPLATE` materialization. **The gate keeps its value outside the template, provided you declare explicitly what you are not materializing.**
- **Additive overlay respected.** `README.md`/`PLAN.md`/`CANON/` untouched; `PLAN.md` received an appended SECTION (build-resume ladder + per-phase EARS clauses) instead of being replaced; `STATUS.md` seeded from the REAL state + machine self-audit + declared coverage limits (the game was never launched: the 18 defects are established by reading with line citations, not by on-screen observation).
